# 抖音商城金鹅商品采集工具

## 项目简介

本项目用于在本地模拟器环境中采集抖音商城里的金鹅相关商品信息。程序通过浏览器自动化、安卓自动化、接口补全和本地签名调试等方式，把商品名称、店铺名称、价格、销量、分享链接等信息整理成便于表格软件打开的数据文件。

项目主要面向本地采集、接口分析、签名链路验证和结果整理，不依赖云端服务，所有运行数据默认保存在本机目录中。

## 主要功能

- 连接本地安卓模拟器并检查抖音商城运行状态。
- 在抖音商城内搜索金鹅相关商品。
- 采集商品卡片、商品详情页和分享链接。
- 对分享页或接口响应进行补全，整理商品名称、店铺、价格、销量和链接。
- 支持断点续跑，减少重复采集。
- 支持访问频率控制和冷却重试。
- 支持网页调试、安卓调试、原生签名链路分析和本地签名验证。
- 输出表格文件、运行摘要、诊断截图和接口响应记录。

## 运行环境

- 系统：视窗十或视窗十一。
- 运行环境：二十或更高版本的节点运行时。
- 安卓环境：木木模拟器已启动，并且可以通过本地调试端口连接。
- 应用状态：模拟器内已安装并登录抖音商城相关应用。
- 浏览器：系统内可使用微软边缘浏览器或其他兼容浏览器。
- 可选环境：用于原生调试的调试框架、用于签名验证的蟒蛇运行时。

默认安卓调试设备地址为：

```powershell
127.0.0.1:16384
```

## 首次安装

在项目目录中执行：

```powershell
npm install
npx playwright install android
npm run probe
```

如果环境正常，探测命令应显示设备已连接，并且目标应用处于可访问状态。

## 常用命令

全量重新采集：

```powershell
npm start -- --all --fresh
```

从上次断点继续全量采集：

```powershell
npm start -- --all
```

重新采集指定数量的商品：

```powershell
npm start -- --limit 20 --fresh
```

从上次断点继续采集指定数量的商品：

```powershell
npm start -- --limit 100
```

指定安卓调试设备地址：

```powershell
npm start -- --serial 127.0.0.1:16384 --limit 20
```

降低分享操作频率并增加冷却时间：

```powershell
npm start -- --limit 20 --max-shares-per-window 6 --share-window-minutes 20 --access-denied-cooldown-minutes 30 --max-access-denied-retries 3
```

检查本地环境：

```powershell
npm run probe
```

运行测试：

```powershell
npm test
```

## 输出文件

默认输出目录为：

```text
output
```

常见输出内容包括：

- 商品结果表：整理后的商品名称、店铺名称、价格、销量和分享链接。
- 运行摘要：记录本次运行数量、错误、状态和断点信息。
- 诊断截图：保存失败现场、页面状态和关键步骤截图。
- 接口响应记录：保存调试过程中捕获到的响应数据。

断点数据默认保存在：

```text
data
```

## 目录说明

```text

```

## 使用流程

一、启动安卓模拟器，并确认目标应用已经登录。

二、在项目目录安装依赖并执行环境探测。

三、根据采集需求选择全量采集、断点续跑或限制数量采集。

四、采集完成后检查输出目录中的结果表和运行摘要。

五、如果页面结构变化或采集失败，查看诊断截图和接口响应记录，再调整选择器、坐标或接口补全逻辑。

## 常见问题

### 设备无法连接

确认模拟器已经启动，安卓调试端口可用，并且设备地址与命令中的参数一致。

### 应用状态不正确

确认目标应用已经安装、已登录，并且没有停留在弹窗、登录页或权限确认页。

### 分享链接复制失败

确认模拟器和系统剪贴板同步正常，并降低分享操作频率后重试。

### 出现访问受限或操作频繁

减少单位时间内的分享次数，增加冷却时间，并使用断点续跑继续采集。

### 结果字段不完整

检查分享页、接口响应和诊断截图，必要时运行接口验证或结果补全脚本。

## 维护说明

- 页面结构变化时，优先检查界面选择、点击流程和诊断截图。
- 接口返回变化时，优先检查数据整理脚本和字段映射逻辑。
- 签名链路变化时，优先查看原生调用链文档和签名验证脚本。
- 上传仓库前先确认忽略规则，避免提交本地数据、缓存和大型二进制文件。
